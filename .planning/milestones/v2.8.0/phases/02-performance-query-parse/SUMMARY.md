## 关键决策

### 1. 前端缓存策略

**决策:** 在 WallpaperService 中添加本地缓存 Map

**理由:**
- Store 中的 `favoriteIds` 未被搜索流程利用
- 前端缓存可减少数据库查询
- 收藏变更时清除缓存，保持一致性

**替代方案:**
- ❌ 在 Store 中管理缓存：需要修改多个组件
- ❌ 使用 LRU 缓存：收藏状态数据量小，简单 Map 足够

### 2. Sharp 库替换手动解析

**决策:** 使用 sharp.metadata() 替换手动二进制解析

**理由:**
- sharp 已安装并用于缩略图生成
- 支持更多格式（WebP, AVIF, TIFF）
- 代码简洁，易于维护

**替代方案:**
- ❌ 完善 WebP 手动解析：复杂度高，维护成本大
- ❌ 使用其他图像库：引入新依赖，sharp 已足够
